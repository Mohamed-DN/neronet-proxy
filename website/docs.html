NeroNet documentation

This page summarises the state of the code. The authoritative documents are in the repository: the engineering handbook (docs/HANDBOOK.md), the roadmap (docs/ROADMAP.md) and the decision records (docs/adr/).

1. Run it locally

The stack and the tests run in containers, with Podman or Docker.

git clone https://github.com/Mohamed-DN/neronet-proxy.git cd neronet-proxy sh scripts/dev/gen-env.sh # .env with fresh random secrets sh scripts/dev/stack.sh up # postgres, valkey, backend, console on 127.0.0.1:8443 sh scripts/dev/stack.sh nodes # two DERP relays and six Go nodes sh scripts/dev/stack.sh status

2. What runs

  • Control plane (console/backend): REST API, WebSocket and the node protocol under /v4/control. State in PostgreSQL 16 and Valkey 7.
  • Console (console/frontend): React application served by nginx.
  • Node (cmd/sovereign-node): enrols, sends a heartbeat every 15 seconds, syncs ACL and route epochs, and runs a local SOCKS5 and HTTP CONNECT proxy that dials destinations directly.
  • DERP relay with STUN (cmd/sovereign-derp-relay): started by the compose stack. No node connects to it.

There is no tunnel between nodes in the default configuration. The overlay address a node is assigned is not configured on an interface, and the ACL policy it downloads is not applied to traffic. A WireGuard data plane exists as a spike behind the node flag -dataplane; it is off by default.

4. Onion routing

The control plane selects a three-hop path and reports how independent the hops are. The library that seals a cell for each hop exists and is tested. No node builds a circuit or sends a cell yet. Onion routing hides traffic from network observers and from the destination. It does not hide it from the operator of the mesh.

5. Deployment

The compose stack is the only deployment that has been run. The order of work is a single virtual machine with compose and systemd, then high availability on three virtual machines, then Kubernetes. The Helm chart, the Kustomize overlays and the Terraform modules in the repository have never been applied to a cluster or a cloud account and are not supported.

6. Security status

  • Secrets are never committed. The backend refuses to start in production on a missing or previously committed secret.
  • Nodes authenticate with one enrolment token shared by the fleet. Per-node credentials are not implemented.
  • The cryptographic code has had no external review.
  • The edge of the compose stack serves plain HTTP; TLS is not configured there.
